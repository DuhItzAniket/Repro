# Predicate type: Repro reproduction card, v0

`predicateType`: `https://github.com/DuhItzAniket/Repro/blob/main/docs/attestation/reproduction-card/v0.md`
(this page). Schema: [`packages/events/schema/attestation/reproduction-card-v0.schema.json`](../../../packages/events/schema/attestation/reproduction-card-v0.schema.json).
Decision: [ADR-0012](../../adr/0012-card-as-attestation.md). Version 0.1.

## Purpose
An in-toto Statement with this predicate records what Repro ran and observed for one code
change, its Reproduction Card. It lets a policy engine, or a person, check what the card said
without trusting the machine that printed it, once the statement is signed.

**What it does not say.** It does not certify that the change is correct. A card states what
the tests and traces showed, what agents judged (verdicts from language models are judgements,
labelled as such), and what could not be checked. Repro's own exports are unsigned; signing is
done in CI (`actions/attest`, phase I03).

## The Statement
In-toto Statement v1 (https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md):

```json
{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [{ "name": "<repository>", "digest": { "gitCommit": "<head commit>" } }],
  "predicateType": "https://github.com/DuhItzAniket/Repro/blob/main/docs/attestation/reproduction-card/v0.md",
  "predicate": { "...": "below" }
}
```

The subject is the change's head commit. Signed through GitHub (Repro's Action, I03), whose
attestations take `sha256` subjects only, the subject is the card itself instead:
`card.json`, the card's canonical JSON, whose SHA-256 is `cardDigest`.

## The predicate

| Field | What |
|---|---|
| `card` | The Reproduction Card the run published, whole (`packages/events/schema/models/card.schema.json`) |
| `cardDigest.sha256` | SHA-256 of the card's canonical JSON (sorted keys, no whitespace, UTF-8): the run's `card_sha256` |
| `status` | The card's status: `VERIFIED`, `FLAGGED` or `UNVERIFIABLE` (a copy, for policies) |
| `isolationLevel` | The isolation the run achieved, `L0` to `L4`, or null (a copy) |
| `network` | `enforced` or `detected-only`, or null (a copy) |
| `eventLog` | The run's event log up to its card: SHA-256 of its events as canonical JSON lines, and their count |
| `evidence` | Each evidence record the card cites: `name` (its ID), `digest.sha256` of its canonical JSON, `mediaType` `application/vnd.repro.evidence+json` |
| `verifier` | `name` `repro` and the version that ran |
| `notice` | What the attestation does and does not certify, in words |

The copies always equal the card's. A consumer must ignore fields it does not know, as in-toto's
parsing rules say.

## Checking one
`repro.card.exports.card_from_attestation` returns the card only if all of these hold:
- the predicate type is this one;
- the card matches `cardDigest`;
- a subject is the card's head commit, or the card itself (by `cardDigest`);
- the copies equal the card.

`repro export <run> --format in-toto` writes one, and the round trip is exact: the card comes
back byte for byte. Each evidence digest can be checked against the run's event log, which
`repro export` and `repro replay` read.

## Versions
The URI carries the major version, as in-toto's TypeURI asks
(https://github.com/in-toto/attestation/blob/main/spec/v1/field_types.md). Minor versions only
add fields, so a policy that ignores what it does not know keeps working. v0.1 (H04) is the
first.
