# Evaluation protocol (draft pre-registration)

> Status: **draft** (A01). It is refined in J01–J04 and **frozen and tagged before the S2 main
> study (J06)**. After the freeze, every change is recorded as a dated amendment at the end of
> this file. Rationale and sources: ADR-0010 and `../research/06-evaluation.md`.

## 1. Unit of analysis and labels
One (task instance, agent patch) pair.
- **Ground truth:** `CORRECT` / `INCORRECT` / `UNCERTAIN`.
- **System output:** `VERIFIED` / `FLAGGED` / `UNVERIFIABLE`.

## 2. Input contract
Every system receives exactly:
- the repository at `base_commit`, inside its sealed environment image;
- the agent diff;
- the claim text. This is the task's problem statement plus the agent's final summary if a
  trajectory exists. Otherwise it is the fixed template *"Fixes the issue above without
  regressions."*

**Withheld from every system:** the gold patch, test patch, FAIL_TO_PASS/PASS_TO_PASS lists,
hints, and post-PR discussion. The benchmark adapter writes sanitised instances, a test asserts
that no withheld field reaches any system, and the digest of each system's inputs is logged.

## 3. Datasets
| Split | Source | Target size | Use |
|---|---|---|---|
| S0 dev | 2–3 SWE-bench repos with fast suites, plus about 50 seeded plausible-but-wrong patches | ~100 | Debugging and tuning. **Never reported** |
| S1 pilot | SWE-bench Verified: PatchDiff's plausible patches and labels, UTBoost-flagged patches, failing predictions from public experiments | ~300 | Calibration, power re-analysis, memorisation probe. Reported as **contaminated** |
| **S2 main** | Fresh Python tasks created after the reviewer models' training cutoffs (SWE-rebench monthly splits, SWE-bench-Live `test`). Patches generated by us with at least 2 scaffolds × at least 2 model families, at most 2 per instance | **≥ 200 INCORRECT and ≥ 200 CORRECT** (adjudicated) | Headline RQ1–RQ5 |
| S3 in the wild | AIDev Python PRs that can be rebuilt at base. Proxies: verified follow-up fix or revert (INCORRECT) vs neither after 60 days or more (CORRECT) | 100–150 | Exploratory RQ6 |
| S4 synthetic | Rule-based and LLM mutants in S2 repos, stratified by defect class | ~300 | Sensitivity only. Never headline |

The sample-size rationale: exact McNemar, α = 0.05 two-sided, power 0.8. With discordance
around 0.2, about 155 incorrect patches are needed to detect a 10-point difference
(research/06 §4). The estimate is re-computed from S1 discordance in J04.

## 4. Ground-truth procedure
1. **Tier A (automatic).** Hidden tests plus the full developer suite in the official image. A
   failure gives `INCORRECT_auto`. This catches patches that pass F2P/P2P but fail the full suite.
2. **Tier B (automatic, plausible patches only).** UTBoost augmented tests where available, plus
   PatchDiff-style differential tests against the gold patch (×20 reruns to drop flaky tests). No
   divergence gives `CORRECT_auto`. Divergence goes to step 3.
3. **Human adjudication.** Covers all tier-B divergent patches, plus random 15% audits of
   `CORRECT_auto` and of `INCORRECT_auto`. Two independent annotators, blinded to every system's
   output, label CORRECT, INCORRECT or UNCERTAIN, plus a defect class, following a written
   guideline. The decision rule: *would the issue author accept this as fixing the issue without
   breaking documented behaviour?* Disagreements are resolved by discussion. Cohen's κ is
   reported per source.
4. `UNCERTAIN` is excluded from primary metrics. A sensitivity analysis treats it as each class.
5. Labels are **frozen** and version-tagged before any system runs on S2.

## 5. Systems
| ID | System | Notes |
|---|---|---|
| R | Repro (full) | Pinned release, config and prompt versions |
| B0 | CI-only | Existing tests (plus tests the patch adds) on head. Flags any failure or regression vs base |
| B1 | Diff-only LLM reviewer | Same model family and token budget as Repro's reviewers. Pre-registered prompt |
| B2 | Agentic static LLM reviewer | Read-only repository tools, no execution |
| B3 | PR-Agent | Pinned commit (licence re-checked). Pre-registered output→label mapping |
| B4 | Testora | Academic execution baseline, run as published where reproducible |
| — | Commercial reviewers | Only with written permission. Otherwise omitted, with the reason stated |
| Ref | PatchDiff-vs-gold | Oracle-assisted ceiling, not a competitor |

Every LLM system runs k = 5 times per patch at the vendor default or one pre-registered
temperature.

## 6. Metrics
- **Primary** (positive class = INCORRECT):
  - catch rate = P(FLAGGED | INCORRECT);
  - false-flag rate = P(FLAGGED | CORRECT).
  - Both are reported on covered items, together with coverage = P(not UNVERIFIABLE). Bounding
    conversions are shown: UNVERIFIABLE → FLAGGED and UNVERIFIABLE → VERIFIED.
- **Secondary:** precision, F1, MCC, risk–coverage curve, verdict flip rate across k = 5,
  citation validity (on a 50-verdict human sample), missing-item rate, wall-clock median and
  p90 by phase, tokens and cost per PR (list price, dated), CPU-minutes, hardware and OS.
- **Stratification:** plausible vs test-failing patches (the headline emphasises plausible),
  defect class, repository, patch size, S2 vs S1.

## 7. Statistical analysis
- Exact McNemar per baseline, separately on INCORRECT (catch rate) and CORRECT (false-flag
  rate). Holm–Bonferroni across baselines and ablations.
- 95% cluster-bootstrap CIs, resampling repositories, 10,000 resamples. Clustered standard errors
  for model comparisons.
- k = 5 runs per LLM system: mean ± SD per metric, majority-vote verdict, flip rate.

## 8. Ablations (on S2, k = 5)
−traces · −probes · −test-selection (full suite) · −invariants · −agents (deterministic rules
only) · −claims (judge without claim text) · −citation rule (uncited verdicts allowed) · reviewer
model swap (smaller model; different vendor) · single run vs majority of 5.

## 9. Threats to validity (to address in the paper)
- **Construct:** "correct" is defined relative to issue and gold behaviour. Hidden tests are weak
  or over-narrow. *Mitigation:* two-tier labels, human audit, sensitivity analysis.
- **Labels:** annotator bias and many UNCERTAIN cases. *Mitigation:* blinding, two annotators,
  κ, published guideline.
- **Contamination:** headline only on post-cutoff tasks, memorisation probe, S1 vs S2 gap reported.
- **Benchmark tailoring:** dev and test split by repository and time, config frozen before S2,
  no tuning on S2.
- **Baseline strength:** same model, budget and inputs. Prompts published.
- **External validity:** Python and pytest, popular OSS repositories, issue-fix tasks. S3 is
  exploratory.
- **Environment:** flakiness, and Docker on WSL2 timing. Images pinned by digest. Cost
  experiments run on Linux.
- **LLM drift:** model IDs and dates recorded. Raw outputs archived.
